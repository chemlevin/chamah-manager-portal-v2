# חמ״ה — בעלות, התאוששות ואבטחת חיבור MCP

## עקרונות מחייבים
1. בעלות הארגון על הנתונים אינה תלויה בפורטל, ב-MCP או בספק ענן מסוים.
2. `portal_user_profiles` ו-`portal_user_permissions` הן מקור האמת להרשאות משתמשי הפורטל. הרשאת `mcp_full_read_access` מאפשרת קריאה רחבה בלבד; היא **אינה** מפתח בעלות על מסד הנתונים.
3. גישת בעלים לתשתיות Supabase, GitHub ו-Vercel מנוהלת דרך חשבונות הספקים עם MFA; אין להטמיע מפתח עוקף-אימות בקוד, בדפדפן או ב-MCP.
4. כל בקשת MCP חייבת לשאת זהות משתמש מאומתת, להיבדק מול הרשאות עדכניות ב-DB, ולהחזיר רק שדות מורשים. אין להעביר service_role ללקוחות MCP.
5. גישה לנתוני מעונות מוגבלת בשרת לפי `scope_mode` ושיוכי `portal_user_daycares`. גם משתמש עם הרשאת מסך אינו רשאי לגשת למעון אחר, אלא אם קיבל במפורש `mcp_full_read_access` או `is_super_admin`.

## מסלול התאוששות — דורש הגדרה ובדיקה
- חשבון בעלים ל-Supabase, GitHub, Vercel, וספק הגיבוי, עם MFA ומפתחות שחזור שמורים בכספת נפרדת. אין לשמור מפתחות שחזור בריפו.
- גיבוי PostgreSQL אוטומטי, מוצפן, לחשבון אחסון **נפרד** מפרויקט Supabase; לכלול סכמות, נתונים ותלויות, ולוודא ייצוא Auth ו-Storage לפי הצורך. אין להניח שגיבוי DB כולל קבצי Storage.
- מנגנון גיבוי מוגבל הרשאות, שמירת גרסאות בלתי-ניתנות לשינוי לפי מדיניות, התראות על כשל בגיבוי, ותיעוד עלויות.
- תרגול שחזור לסביבה נפרדת לפחות רבעונית: אימות סכמות, נתונים, הרשאות, מסמכים, קבצים וכניסה למערכת.
- תוכנית החלפת ספק: ייצוא נתונים בפורמט פתוח, פריסת קוד מהריפו, שחזור secrets ממנהל סודות מאובטח, שינוי DNS וניתוק מפתחות ישנים.
- אין לסמן גיבויים או שחזור כפעילים עד שבוצעו ונבדקו בפועל.

## בדיקות קבלה לפני פתיחת MCP למשתמשים
- משתמש לא מחובר: 401/403, ללא דליפת נתונים.
- משתמש כבוי: חסום גם עם אסימון שהונפק קודם, בכפוף לאימות שרת.
- לאה: מעון מחנה בלבד, ניסיון גישה לאשקלון חסום.
- הרשאת צפייה: קריאה בלבד, ללא כתיבה.
- משתמש בעל `mcp_full_read_access`: קריאה מכל המעונות; ביטול הרשאה נכנס לתוקף בבקשה הבאה.
- מנהל־על: קריאה מלאה, אך ללא עקיפת אימות.
- פרוטוקול MCP: OAuth, הגבלת קצב, יומן קריאות שאינו מכיל מידע רגיש, טיפול בשגיאות, מניעת prompt injection ו-exfiltration.
- בדיקת חדירה / בדיקות הרשאות אוטומטיות לפני הרחבה למידע על עובדים ושכר.

## ספקים אפשריים (לא חוברו)
- Cloudflare: WAF, rate limiting והגנה על endpoint ציבורי.
- Sentry: ניטור שגיאות, עם סינון PII וסודות.
- ספק אחסון גיבויים נפרד (S3-compatible או דומה): דורש בחירת ספק, תקציב והגדרת retention.
- מנהל סודות/כספת ארגונית: חשבונות בעלים, MFA, recovery codes.

## מצב נוכחי
ממשקי קריאה לנהלים ולרשימות מעונות קיימים ב-DB; מתג MCP נוסף לקוד ניהול המשתמשים; **שרת MCP ציבורי עם OAuth, גיבוי חיצוני ותרגול שחזור טרם הושלמו**.
